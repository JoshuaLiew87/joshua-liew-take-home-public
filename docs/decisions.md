# Decision log

## Day 1 foundations

- **A-001 — Coordinate convention:** pixel centers are integer coordinates and pixel boundaries are half a pixel away. This keeps the simulator, estimators, and theory consistent.
- **A-002 — Array/coordinate order:** represent a spot position as `(x, y)` while storing images as `image[y, x]`. This matches the usual array convention without confusing coordinate order.
- **A-003 — Pixel integration:** render the Gaussian by integrating its probability mass over each pixel area rather than sampling only at pixel centers. This avoids making the simulator's sub-pixel behavior an artifact of point sampling.
- **A-004 — Brightness parameter:** use total expected spot electrons as the physical brightness parameter. The experiment layer exposes target SNR values and maps them to total flux.
- **A-005 — Spot width:** use a nominal sigma of 1.75 pixels because a 7-pixel 1/e² diameter implies `sigma = diameter / 4`.
- **A-006 — RNG isolation:** use named NumPy random-number-generator streams derived from one master seed. This prevents unrelated experiments from changing each other's random sequences.
- **A-007 — Scenario profiles:** keep ideal, sensor, and dynamic profiles in one configuration model. This avoids duplicating simulator logic while making assumptions visible.
- **A-008 — Initial sensor geometry:** use 32×32 pixels and 1 ms/1 kHz as initial sensor defaults. This is large enough to contain the spot and small enough for rapid experiments.
- **A-009 — PRNU convention:** apply a persistent multiplicative PRNU gain to expected total charge before Poisson sampling. This is a simple, explicit sensor-response convention; it affects both mean charge and shot-noise statistics.
- **A-010 — Hot-pixel model:** represent hot pixels as persistent locations with elevated dark-current rates. This preserves stochastic dark noise while creating fixed spatial outliers.
- **A-011 — Readout convention:** add Gaussian read noise in electrons, convert using electrons/DN, then round to nearest DN when quantization is enabled. This provides explicit units and a testable ADC model.
- **A-012 — SNR convention:** calibrate target SNR using a reference spot centered on a pixel and record the actual effective SNR separately. This avoids defining the sweep through a random sub-pixel phase.
- **A-013 — Sigma variation:** use 5% RMS sigma variation only in stressed scenarios; keep sigma fixed in the clean reference. This tests optics variation without obscuring the clean estimator comparison.
- **A-014 — Default stressed sensor parameters:** use 1% PRNU, 50 electrons/s baseline dark current, 4 hot pixels at 5,000 electrons/s, 3 electrons RMS read noise, 12-bit ADC, and 1 electron/DN. These are engineering assumptions for a controlled simplified scenario, not camera measurements.
- **A-015 — Noise ablations:** expose independent switches for photon shot noise, read noise, dark current, background, PRNU, and hot pixels. This makes it possible to attribute behavior to individual effects without duplicating the simulator.
- **A-016 — Visual sanity check:** use a small Matplotlib diagnostic tool that calls the same simulator API as later experiments. This helps detect PSF, noise, SNR, and saturation mistakes without creating a separate simulation implementation.
- **A-017 — Shared estimator input contract:** use full-frame brightest-pixel detection followed by a local odd-sized ROI, with 13×13 for the centroid and 15×15 for the Gaussian fit initially. This keeps the comparison fair and makes ROI/runtime tradeoffs configurable.
- **A-018 — Centroid background policy:** fit a constant or planar background to the ROI border, subtract it, and clamp negative residuals to zero before calculating weights. This is simple and robust for the baseline gradient model, but may remove weak PSF tails at low SNR.
- **A-019 — Gaussian parameterization:** fit position, total flux, sigma, and a planar background using the pixel-integrated Gaussian forward model. This avoids a point-sampled model mismatch and makes the fitted nuisance parameters explicit.
- **A-020 — Gaussian optimizer policy:** use bounded SciPy `least_squares` with an analytical Jacobian, two fixed IRLS reweighting steps, and ADC-limit masking. The fixed iteration count makes runtime predictable; this remains a quasi-MLE under the simplified sensor model.
- **A-021 — Live GUI architecture:** reuse the production simulator, shared trajectory generator, and estimator interfaces in the interactive demonstration. This prevents the visual demo from drifting away from the reproducible analysis model.
- **A-022 — GUI timing:** default the display timer to 50 ms and label it as display-only. A GUI refresh rate is not a substitute for the dedicated per-frame estimator benchmark against the 1 kHz sensor interval.
- **A-023 — GUI trajectory sanity mode:** use bounded sinusoidal drift, correlated jitter, and one sinusoidal disturbance in the current live GUI and early sanity checks. The initial defaults are 1.5 pixels drift amplitude at 0.4 Hz, 0.04 pixels jitter RMS with 0.95 correlation, and a 0.05-pixel 73 Hz disturbance. This mode is easy to inspect visually but is not the preferred final dynamic-scene model.
- **A-024 — Final dynamic drift model:** use bounded correlated stochastic drift implemented as a discrete Ornstein–Uhlenbeck process, equivalent to a first-order AR(1)/low-pass filtered random process. Expose its nominal stationary RMS, correlation time, position bounds, and saved seed. This avoids the unbounded behavior of Brownian motion and leaves the 73 Hz sinusoid as the one intentional periodic disturbance. The final values are 0.6 pixels RMS before bounding, 0.25 seconds, and ±2 pixels.
- **A-025 — Static characterization protocol:** use one reproducible set of random sub-pixel positions for all requested SNR values, keep fixed-pattern maps constant for the sweep, evaluate both estimators on the same rendered frame, and save bias, standard deviation, RMSE, failure rate, and outlier rate in CSV/JSON form. The final lock-loss threshold is 1 pixel.
- **A-026 — Gaussian IRLS variance floor:** use a configurable 1 DN² lower bound on the approximate Poisson/read-noise variance during Gaussian fitting. This prevents tiny negative or near-zero background-model values in PSF tails from creating numerically dominant weights, while keeping the fit's approximate-likelihood status explicit.
- **A-027 — Runtime benchmark protocol:** generate and store the benchmark frames before timing, exclude a documented warm-up period, report percentile and worst-case latency, and compare each call with the 1 ms frame interval. Measure centroid cold-start and Gaussian cold/warm-start paths separately so simulator cost and initialization effects are not conflated with steady estimator cost.
- **A-028 — Final dynamic analysis:** use a 5,000-frame, 1 kHz record with 0.6-pixel OU drift RMS, 0.25-second correlation time, ±2-pixel bounds, 0.04-pixel correlated jitter, and one 73 Hz, 0.05-pixel x-axis disturbance. Apply a Hann window, exclude frequencies below 20 Hz during disturbance identification, and refine the spectral peak with sinusoidal least squares.
- **A-029 — Controlled outdoor stress scope:** quantify selected Phase 6 effects with 300 paired trials at reference SNR 10 and a 1-pixel lock-loss threshold. Hold nominal photon flux fixed for background and defocus cases so their information loss is measurable rather than hidden by SNR recalibration. The study supplements, rather than replaces, the required qualitative outdoor analysis.
- **A-030 — Scintillation stress model:** represent scintillation as a mean-one correlated log-normal flux multiplier with log-intensity RMS 0.5 and lag-one correlation 0.95. This captures temporal intensity modulation and effective-SNR variation without conflating it with beam wander; it is an engineering stress model, not a field-atmosphere claim.
- **A-031 — Outdoor stress levels:** use sigma = 2.4 pixels for defocus, a 200-electron/pixel background with 1.5/-1.0 electron/pixel gradients, and 100x nominal flux for saturation. These values produce visible but interpretable estimator degradation within the existing 32x32 sensor model; blooming, halos, and motion-blur physics remain analysis-only limitations.
- **A-032 — GUI review shortcuts:** keep manual 0.1-pixel nudges, SNR 1/1,000 flux presets, a background-gradient toggle, and a fixed ROI-edge hot-pixel injection in the optional GUI only. These controls make failure modes visible during review without changing reproducible offline experiments.
- **A-033 — Configurable Gaussian speed study:** keep the full-quality acquisition defaults at a 15×15 ROI, two IRLS passes, and the existing optimizer limit, while exposing a fast tracking profile with a 13×13 ROI, one IRLS pass, a 30-evaluation limit, previous-position ROI placement, and skipped centroid reinitialization. This isolates speed/accuracy tradeoffs without changing the primary estimator comparison.
- **A-034 — Runtime sequence scope:** report fixed-position acquisition timing separately from sequential dynamic-trajectory timing. The former isolates estimator cost on independently noisy frames; the latter is the relevant test for warm-start behavior during tracking.
- **A-035 — Ranking-reversal ablation:** run 250 paired trials at SNR 1 and 3 for ideal, background-gradient, PRNU/hot-pixel, quantization/saturation, and full-stressed conditions. This isolates whether the observed estimator reversal is caused by background modeling, outliers, clipping, or low-SNR convergence.
- **A-036 — Dynamic amplitude repeat:** run five independent master seeds with 2,500 frames per seed at target SNR 10. Use this as a repeatability study for amplitude bias; retain the 5,000-frame run as the primary frequency-recovery result.
- **A-037 — Conversion-gain validation:** explicitly test a 2-electron/DN case with separate full-well and ADC limits. The nominal 1-electron/DN setting is convenient but must not be the only unit-ordering check.
- **A-038 — GUI illumination and exposure demonstration:** keep the day/night control display-only and separate from the authoritative batch experiments. Map the scene midpoint to the nominal beacon/background levels, sweep beacon flux over a broad illustrative range, and use bounded exposure scaling plus a simplified analog-gain convention to respond to saturation or underexposure. This demonstrates the optional automatic-exposure concept without claiming calibrated camera-driver behavior or changing the reproducible `run_all.py` results.

## Assumption-register requirements

Every later material choice must receive the next stable `A-###` identifier and include its value, units, rationale, expected effect, and validation or limitation. The final report must reproduce this information in its assumption register and map each entry to the relevant experiment or result.
